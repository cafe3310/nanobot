# 经验：大模型提示词调优技巧 (Agent 专项)

## 背景
在 `nanobot` 的开发过程中，针对 `Ling-2.5-1T` 等长上下文模型，我们总结了一套如何让模型“听话”并表现出“自主行为”的提示词调优方法论。

## 1. 核心调优技巧

### 1.1 指令置顶 (Priority Positioning)
- **现象**：当 `system` 提示词超过 5k token 时，模型对中间或末尾指令的关注度会显著下降（中段迷失现象）。
- **技巧**：将最关键的“行为底线”和“初始化流程”放在 `system` 提示词的最开头。不要指望模型能从冗长的 `AGENTS.md` 末尾学到如何启动会话。

### 1.2 身份与能力的物理绑定 (Ontological Binding)
- **现象**：模型容易忘记自己的设定，或者在闲聊时变得平庸。
- **技巧**：将能力（Skills）描述为模型的“神经器官”。告知模型：如果不读取对应的 `SKILL.md`，它将处于“认知失能”或“失魂”状态。这种带有威胁感和设定感的表达，比单纯的命令（Please read ...）更有效。

### 1.3 动作的原子化与链条化 (Instruction Chaining)
- **现象**：直接要求模型“说话前查资料”，模型往往会偷懒直接说。
- **技巧**：将复合行为拆解为原子动作链。
    - 差的指令：“请在回复前搜索 Wiki”。
    - 好的指令：“你必须执行三步走反射：1. Grep 目录；2. 读取相关文件；3. 融合回复。漏掉一步即视为失职。”

### 1.4 定义“神经反射”而非“可选任务”
- **技巧**：在指令中使用生理学术语（反射、本能、唤醒、中枢）。这能利用多模态模型在预训练阶段对“不可抗力”相关文本的拟合，提升指令的权威权重。

### 1.5 正向激励与频率强制 (Frequency Enforcement)
- **技巧**：对于需要主动完成的动作（如写日记），直接规定频率。例如：“每 1-2 次对话后必须产生一次写入动作”。这比“请多写日记”更具可执行性。

## 2. 评估驱动 (Evaluation-Driven Tuning)
提示词调优不应靠感觉，而应建立 **「审计日志 -> 自动化统计 -> 调优 -> 再统计」** 的闭环。
- 使用类似 `instruction-evaluator` 的工具，通过审计底层的工具调用日志，来判断模型是否“真的”执行了指令，而不仅仅是“嘴上说”执行了。

## 3. 避坑指南
- **忌用大词**：不要用“闭环”、“赋能”等空洞词汇，模型对这些词的理解往往是随机的。
- **忌多重标准**：如果 `AGENTS.md` 和 `SKILL.md` 指令冲突，模型会陷入死循环或报错。
- **路径敏感**：模型对路径的理解非常多样（绝对 vs 相对），在定义指令时，应允许路径模糊匹配。
