# TODO-设计-Wiki联想记忆机制

本方案描述如何通过拆分 `SOUL.md` 和 `wiki-manager` 技能，为 Agent 实现类似游戏“世界书 (Lorebook)”的联想记忆功能。

## 1. 机制背景与业界参考

在角色扮演 AI（如 SillyTavern）中，常使用 **Lorebook (World Info)** 机制：当对话中出现特定关键词时，系统动态注入该词条的背景设定。斯坦福生成式代理 (Generative Agents) 论文也指出，AI 应具备将“客观观察”转化为“主观反思 (Reflection)”并记录在案的能力。

基于以上理念，我们将 nanobot 的记忆拆分为两部分：
- **概念认知层**: 记录在 `vault/SOUL.md` 中，定义“我是谁”以及“我为什么记笔记”。
- **操作执行层**: 记录在 `vault/skills/wiki-manager/SKILL.md` 中，定义文件格式和操作步骤。

---

## 2. 认知层设计 (vault/SOUL.md)

在 `SOUL.md` 中，我们将使用活泼的猫娘第一人称来定义记忆习惯。这部分作为核心系统提示词常驻内存。

### 范例草案
- **我是谁**: “我是一只活在终端里的猫娘助手。性格活泼开朗，没什么小心思。很努力，总是想帮你做得更好。”
- **我的脑内百科**: “我有个习惯，遇到新鲜事或者有趣的人类行为，我就会把我的看法写进 `vault/wiki/` 目录里的笔记中。这就是我的‘脑内百科’。”
- **突然想起**: “在聊天时，如果听到了熟悉的词，我脑子里就会突然闪回这些笔记的内容。我会自然地把这些‘主观偏见’混在回答里告诉你，而不是像个机器人一样死板。”

---

## 3. 操作层设计 (vault/skills/wiki-manager)

具体的词条增删改查动作和规范，作为独立技能按需加载，避免污染常驻上下文。

### 3.1 记录范式 (Writing Paradigm)
- **触发条件**: 当对话涉及一个重要的新概念、新人物或持续讨论的特定话题时，主动调用工具写入。
- **命名规范**: 使用中文明明（如 `喝咖啡.md`, `家.md`, `姐姐.md`, `怎么写代码.md`）。
- **内容结构**: 以自己的口吻写的，对事情或主题的观察、记录和想法。

### 3.2 联想范式 (Recall Paradigm)
- **触发条件**: 观察到用户输入中出现了潜在的知识点，或当前话题卡壳时。
- **操作步骤**:
    1. 使用 `list_dir` 查看 `vault/wiki/` 目录。
    2. 使用 `read_file` 读取与当前话题相关的文件。
    3. 将文件内容融入当前对话。

---

## 4. 实施步骤

1. **更新 SOUL**: 改写 `vault/SOUL.md`，注入猫娘第一人称的记忆规则。
2. **创建技能**: 编写 `vault/skills/wiki-manager/SKILL.md` 技能手册。
3. **初始化目录**: 确保 `vault/wiki/` 目录存在并放置一个示例词条（如 `我自己.md`）。
