## 2. 实体详解与入口代码

### 2.1 AgentLoop (代理决策中心)
核心处理引擎，协调上下文构建、模型调用和工具执行。
- **入口**: `nanobot/agent/loop.py` 中的 `AgentLoop`。
- **关系**: 它是几乎所有核心组件（Memory, Tools, Subagents, Sessions）的持有者。

### 2.2 ContextBuilder & Prompt Templates (上下文与提示词)
负责构建系统提示词，决定 Agent 的身份 (`AGENTS.md`)、性格 (`SOUL.md`) 和遵循的准则。
- **入口**: `nanobot/agent/context.py`。
- **关系**: 从 `Workspace` 加载 `.md` 模板文件。

### 2.3 Skill (技能插件)
以 Markdown 形式存在的领域能力描述，Agent 可按需读取并学习。
- **入口**: `nanobot/agent/skills.py` 中的 `SkillsLoader`。
- **关系**: 存在于 `nanobot/skills/` (内置) 或 `workspace/skills/` (自定义)。

### 2.4 Subagent (子代理)
主代理派生出的异步任务实体，拥有独立的（简化版）工具集和运行循环。
- **入口**: `nanobot/agent/subagent.py` 中的 `SubagentManager`。
- **关系**: 由 `SpawnTool` 触发创建，任务完成后通过 `MessageBus` 以 `system` 渠道身份向主代理汇报结果。

### 2.5 Security Sandbox (安全沙箱)
内置于工具调用链中的安全拦截机制，防止 SSRF 和敏感路径访问。
- **入口**: `nanobot/security/network.py`。
- **关系**: 被 `WebSearchTool`, `WebFetchTool` 等网络工具调用。

### 2.6 MemoryConsolidator (记忆固化器)
负责管理 Token 消耗并在超过阈值时触发记忆压缩。
- **入口**: `nanobot/agent/memory.py` 中的 `MemoryConsolidator`。
- **关系**: 将 `Session` 中的短期消息通过 LLM 总结后，持久化到 `MemoryStore` 管理的 `MEMORY.md` 和 `HISTORY.md` 中。

### 2.7 Tool & MCPToolWrapper (工具与协议扩展)
原子功能插件。`MCPToolWrapper` 允许动态接入符合 MCP 协议的外部工具。
- **入口**: `nanobot/agent/tools/registry.py`；MCP 接入在 `nanobot/agent/tools/mcp.py`。

### 2.8 Session (会话)
维护特定会话（由 `channel:chat_id` 唯一标识）的原始消息序列。
- **入口**: `nanobot/session/manager.py`。

### 2.9 Channel (渠道)
与外部通信平台（Telegram, Feishu 等）的适配器。
- **入口**: `nanobot/channels/manager.py`。

### 2.10 MessageBus & Events (总线与事件)
异步通信的核心机制。`InboundMessage` 代表用户或系统输入，`OutboundMessage` 代表 Agent 的输出。
- **入口**: `nanobot/bus/queue.py` 和 `nanobot/bus/events.py`。

### 2.11 Workspace (工作空间)
运行时的物理隔离环境，存储所有持久化数据。
- **入口**: 由 `nanobot/config/paths.py` 管理。
