# 开发日志：大模型错误自愈与抢救上下文机制实现 (2026-03-25)

## 背景与目标

为了解决模型在遇到工具调用错误（如 400 错误、工具不存在等）时直接中断执行、缺乏自愈能力的问题，我们今天实现了基于「错误恢复上下文」的自愈机制。
在此之前，这类错误会导致 Agent 立即停止工作，并将生硬的技术报错展示给用户。

---

## 主要工作项

### 1. 核心循环拦截 (error_patch.py)
- **拦截点**: 通过 Monkey Patch 替换了 `AgentLoop._run_agent_loop`。
- **状态维持**: 在循环内部引入了 `error_retry_count`，允许针对同一任务进行最多 2 次自愈重试。
- **历史回填**: 不同于原版「丢弃错误响应」的做法，我们将原始错误作为 `assistant` 消息回填到消息序列中，让模型意识到自己刚才的失败。

### 2. 抢救上下文注入
- **自定义模板**: 定义了 `ERROR_RECOVERY_TEMPLATE`，包含对工具名校验、参数闭合以及特定工具（如 `agent-browser`）使用规范的深度指导。
- **动态构造**: 当检测到 `finish_reason == "error"` 时，构造以下格式的消息推给模型：
    ```
    错误信息
    --------
    [原始报错内容]
    [自愈建议模板]
    ```

### 3. 即时生效与集成
- **补丁激活**: 在 `launcher.py` 中将 `apply_error_patch` 加入早期注入队列。
- **安全保障**: 仅针对逻辑/调用层面的错误进行重试；对于重试次数耗尽或严重平台错误，依然保持安全中断。

---

## 验证结果

- **逻辑覆盖**: 补丁已成功接管 Agent 循环。
- **预期行为**: 当模型尝试非法调用 `agent-browser` 时，它将收到「该工具需通过 exec 执行」的提示，从而获得在当前 Turn 内修正命令的机会。

---
## 经验与教训

1. **变废为宝**: 报错信息对人类是烦恼，对模型却是宝贵的「负反馈」信号。将其转化为结构化的上下文，能极大地提升自动化系统的鲁棒性。
