# 调研与设计：金库功能扩展方案 (Vault Expansion)

## 1. 核心挑战与解决思路

**挑战**：在早期的安全加固中，我们全局禁用了 `exec` 工具，以防止 Agent 执行 Shell 命令影响系统。然而，Git、FFmpeg、ImageMagick 等多媒体与代码管理功能，通常依赖底层的 Shell 调用。

**解决思路**：
- **能力请求外部化**: 引入标准 MCP 服务器（如 Browser 和 GitHub）。
- **受控 Shell 的恢复**: 在 `vault` 中开发专用的「白名单命令执行 MCP 服务器」，将 `git`, `ffmpeg`, `gemini`, `magick` 封装为 API。
- **业务逻辑指令化**: 将「如何备份」、「如何整理 Wiki」编写为 `vault/skills/` 下的指令。

## 2. 能力实施方案分解

### 方案 A：引入官方 MCP Server (零代码开发)

针对标准化程度高、生态成熟的需求，直接在 `vault/mcp.json` 中配置官方支持的服务器。

- **1. 浏览器使用**
  - 实施方案：接入官方 Puppeteer MCP
  - 资源来源：`npx -y @modelcontextprotocol/server-puppeteer`
- **8. Github Issue 写文章**
  - 实施方案：接入官方 GitHub MCP
  - 资源来源：`npx -y @modelcontextprotocol/server-github`

*说明：这需要在宿主机安装 Node.js，并在 `vault/mcp.json` 中配置相应的环境变量（如 `GITHUB_PERSONAL_ACCESS_TOKEN`）。*

### 方案 B：开发「白名单沙盒」本地 MCP (解决安全执行)

针对依赖命令行工具的需求，我们将编写一个 Python 脚本 `cafeext/vault/mcp/safe_exec_server.py`，它暴露一个名为 `safe_execute` 的工具，但在内部校验命令前缀。

- **2. ImageMagick 处理**
  - 白名单前缀：`magick `, `convert `
  - 适用场景：裁剪、压缩、格式转换
- **3. Git 处理**
  - 白名单前缀：`git `
  - 适用场景：状态检查、提交、推送
- **4. FFmpeg 媒体处理**
  - 白名单前缀：`ffmpeg `, `ffprobe `
  - 适用场景：视频剪辑、音频提取
- **6. 控制 gemini-cli**
  - 白名单前缀：`gemini `, `nb `
  - 适用场景：发起子任务、查询其他项目

*特点：即使 Agent 尝试执行 `rm -rf`，也会被专用的 MCP 服务器拦截。这实现了在安全前提下使用 Shell 工具。*

### 方案 C：编写 Vault Skills (工作流与逻辑定义)

对于业务逻辑复杂的复合操作，无需开发新代码，而是利用我们在 `vault/` 中「Skills」特性，教导 Agent 如何使用现有工具（内置读写工具 + 上述 MCP 工具）。

- **5. 整理记忆 Wiki**
  - Vault Skill 名称：`wiki-manager`
  - Skill 核心逻辑：指导 Agent 使用 `list_directory` 扫描 `vault/wiki/`，并使用 `write_file` / `replace` 以固定 Markdown 模板记录事实。定义词条的分类标准和索引更新机制。
- **7. 备份 Workspace 与 Vault**
  - Vault Skill 名称：`repo-backup`
  - Skill 核心逻辑：指导 Agent 组合调用 `safe_execute` 执行 `git status`, `git add .`, `git commit -m "Auto-backup"`, `git push`。并且明确规定它在备份前应该忽略哪些临时文件。

## 3. 实施路线图 (Roadmap)

按以下三个阶段实施：

**阶段 1：环境基础设施建设**
1. 创建 `cafeext/vault/mcp/` 目录。
2. 编写 `safe_exec_server.py`。
3. 修改 `vault/mcp.json`，配置好 `safe-exec`, `github` 和 `puppeteer` 三个节点。

**阶段 2：编写核心工作流 Skills**
1. 在 `vault/skills/` 下创建 `wiki-manager/SKILL.md`。
2. 在 `vault/skills/` 下创建 `repo-backup/SKILL.md`。

**阶段 3：测试与微调**
1. 重启 Bot (`nb agent`)。
2. 尝试下达指令：“帮我给今天的对话写一个 Wiki 词条，然后把项目推送到 Github 备份”。
3. 观察日志中 MCP 调用 and 文件写入的执行流。
