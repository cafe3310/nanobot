# 需求：工具执行白名单机制 (Automatic Tool Execution Whitelist)

## 1. 背景 (Context)

目前 `nanobot` 的所有工具执行（除了 `message`）都需要经过人工确认（终端或 macOS 对话框）。虽然这保障了安全性，但在执行大量只读操作（如频繁的 `read_file`）或一些安全的自动化脚本时，频繁的弹窗会极大地降低操作流畅度。

我们需要一套灵活的白名单机制，允许在满足特定条件时自动放行工具执行，无需用户手动点击。

---

## 2. 功能目标 (Goals)

1. **规则灵活**: 支持基于工具名称 (`name`) 和参数 (`args`) 的自定义逻辑判断。
2. **易于扩展**: 允许通过一系列规则条目来定义放行逻辑。
3. **安全透明**: 即使工具被自动放行，其执行记录依然应出现在审计日志中，并在终端有简要提示。

---

## 3. 设计方案 (Proposed Design)

### 3.1 规则定义 (Rule Structure)
每个白名单规则是一个对象或字典，包含：
- `name_rule`: 一个 Lambda 或函数，接收工具名称，返回 `bool`。
- `args_rule`: 一个 Lambda 或函数，接收工具参数字典，返回 `bool`。
- `description`: 对该规则的简短描述，用于日志或提示。

### 3.2 拦截逻辑调整 (security.py)
在 `patched_execute` 中，引入白名单检测阶段：
1. **匹配检测**: 遍历规则列表。如果某个规则的 `name_rule` 和 `args_rule` 均返回 `True`，则视为匹配成功。
2. **静默放行**: 若匹配成功，跳过人工确认阶段，直接进入执行环节。
3. **终端提示**: 在执行前打印一条简短消息，如 `[WHITELIST] Auto-approving 'read_file' (Reason: Read-only access)`。

---

## 4. 实施计划 (Implementation Plan)

### 第一阶段：定义规则容器
- 在 `cafeext/py/wrapper/security.py` 或 `config.py` 中定义白名单规则列表。
- 预设初始规则：
    - 允许所有 `read_file`, `list_dir`, `list_directory`。
    - 允许特定的 `exec` 命令（如：以 `cat ` 开头且不含 `&&`, `;`, `|` 的命令）。

### 第二阶段：重构 `patched_execute`
- 提取白名单匹配逻辑为独立函数。
- 在人工确认逻辑前插入白名单检测。

### 第三阶段：验证与日志
- 验证自动放行的工具是否正确触发审计日志。
- 确认终端输出是否清晰区分了「人工确认」和「自动放行」。

---
## 5. 示例规则 (Code Example)

```python
WHITELIST_RULES = [
    {
        "name": lambda n: n in ["read_file", "list_dir", "list_directory"],
        "args": lambda a: True,
        "description": "Allow all read-only filesystem operations"
    },
    {
        "name": lambda n: n == "exec",
        "args": lambda a: a.get("command", "").startswith("cat ") and "&&" not in a.get("command", ""),
        "description": "Allow simple cat commands"
    }
]
```
