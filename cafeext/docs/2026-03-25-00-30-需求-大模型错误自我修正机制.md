# 需求：大模型错误自我修正机制 (Self-Correction for LLM Errors)

## 1. 背景 (Context)

在 `nanobot` 的运行过程中，模型有时会产生「幻觉」，尝试调用并不存在的工具（如直接 Tool Call `agent-browser` 而非通过 `exec`）。目前的 `AgentLoop` 处理逻辑非常生硬：一旦检测到 `finish_reason == "error"`（包含 400 报错），会立即打印错误日志并中断执行，将报错直接反馈给用户。

这导致了两个问题：
1. **用户体验差**: 用户看到的往往是晦涩难懂的技术报错。
2. **缺乏自愈能力**: 模型本身没有机会看到报错信息，也无法通过调整策略来修正错误。

---

## 2. 研究发现 (Research Findings)

在 `nanobot/agent/loop.py` 的 `_run_agent_loop` 方法中：
- 系统检测到 `response.finish_reason == "error"` 后，会直接 `break` 循环。
- 为了防止「毒上下文」导致的死循环，错误信息被禁止存入会话历史。
- 报错信息（如：`LLM is trying to invoke a non-exist tool...`）只存在于后台日志和发送给用户的最终回复中，模型在下一轮对话前对该错误一无所知。

---

## 3. 改进方案 (The Plan)

我们计划引入一套「错误恢复上下文」，允许模型在遇到可修复错误时进行自救。

### 3.1 拦截与抢救 (The Hook)
通过 Monkey Patch 拦截 `AgentLoop._run_agent_loop`：
1. **捕获错误**: 当 `finish_reason == "error"` 且错误信息包含特定模式（如非存在工具、参数错误）时，不立即中断。
2. **构建修正消息**:
    - 将原始错误信息作为背景。
    - 注入一段**强力的引导提示（Recovery Context）**，例如：
      > 「你刚才尝试调用的工具 '{tool_name}' 并不存在。请检查你的工具定义列表。注意：`agent-browser` 必须通过 `exec` 工具以 CLI 命令行形式运行。」
3. **推回循环**: 将修正后的消息序列重新推给模型，让其生成新的响应。

### 3.2 限制与防御 (Guardrails)
- **重试上限**: 针对同一轮任务，错误修正重试次数限制为 1-2 次，防止无限循环消耗 Token。
- **状态感知**: 仅针对「模型操作层面」的错误（400/Tool Error）进行自救，对于「平台/认证层面」的错误（401/500）依然保持中断逻辑。

---

## 4. 实施步骤 (Implementation)

1. **创建补丁**: 在 `cafeext/py/wrapper/error_patch.py` 中实现拦截逻辑。
2. **定义提示词**: 编写针对不同错误类型的「猫式叮嘱」修正模板。
3. **整合加载**: 在 `launcher.py` 中激活该补丁。
4. **验证验证**: 通过构造错误的工具调用（如直接让模型搜 jandan.net）来测试其是否能成功自愈。
