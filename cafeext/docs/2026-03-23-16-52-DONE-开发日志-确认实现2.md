# 开发日志：人工确认拦截器实现 (HITL Multi-modal Confirmation)

## 1. 任务背景 (Context)

在开放 `exec` 权限后，为了保持对 Agent 行为的控制，需要在工具执行前注入人工决策环节。目标是提供在不影响开发节奏的前提下，提供安全保障的交互方式。

---

## 2. 主要工作 (Tasks Completed)

### 2.1 多种交互确认 (Multi-modal Confirmation)
- **视觉反馈**: 实现了 macOS 对话框 (`display dialog`)。通过 AppleScript 将确认窗口推至前台，显示工具名及参数预览。
- **听觉提醒**: 在触发确认面板时同步发出终端响铃 (`\a`)，提醒用户注意。
- **快捷操作**: 引入了终端 `cbreak` 模式下的单键捕获 (`get_char`)。用户按下 `1` (允许) 或 `2` (拒绝) 即可做出决定。

### 2.2 拦截逻辑 (Mechanism)
- **双重后备**: 如果 macOS 对话框由于环境问题未能显示，系统会自动退回到终端按键确认模式。
- **语义化反馈**: 当用户拒绝执行时，系统会向 Agent 返回 `[Operation Cancelled]` 消息，使 LLM 理解中断原因。
- **自动跳过**: 逻辑上跳过了 `message` 工具，确保正常聊天对话不被中断。

---

## 3. 技术实现细节 (Technical Details)

### 3.1 核心模块
- **`notification.py`**: 封装 AppleScript 逻辑。使用 `frontmost application` 承载对话框，解决进程 UI 权限导致的显示问题。
- **`security.py`**: 整合拦截逻辑。对 `ToolRegistry.execute` 进行拦截，将审计日志、铃声、弹窗、终端捕获整合进执行流程。

---

## 4. 后续计划 (Next Steps)

1. **分级确认策略**: 根据工具类型（只读、写入、执行）自动切换通知方式。
2. **原因反馈**: 在弹窗中增加输入框，允许在拒绝时提供理由，辅助 Agent 进行调整。
