# 设计：双层记忆与存储上下文布局 (Dual-Layer Vault Context)

## 1. 设计初衷与目标

在赋予 Agent 操作系统级别的能力后，保护其核心指令与设定免受意外篡改（或幻觉写入）变得至关重要。
本设计通过建立物理隔离的 `cafeext/vault/`（记忆存储），实现了以下目标：
1. **层级化权威 (Hierarchical Authority)**：将记忆分为「核心层」与「扩展层」，明确声明 Vault 具有最高优先级。
2. **多源叠加加载**：如果同名文件同时存在于 Vault 和 Workspace，系统将同时加载它们并标注权重差异，确保角色设定既稳定又灵活。
3. **隔离写保护**：Agent 只能向存储中的 `BOT.md` 写入经验总结，无法触碰 `SOUL.md` 或 `USER.md` 等核心文件。

## 2. 层级化补强后的上下文布局 (Hierarchical Context Layout)

以下是经过 `context_patch.py` 拦截并注入后的最终上下文内存排布示意图：

### SYSTEM PROMPT
1. **01. IDENTITY**: # nanobot 🐈
2. **02. BOOTSTRAP** (引导层双层叠加, Delimiter: ---)
    - ## 🛡️ [CORE AUTHORITY] AGENTS.md
    - ## 📄 [EXTENDED CONTEXT] AGENTS.md
    - ## 🛡️ [CORE AUTHORITY] SOUL.md
    - ## 📄 [EXTENDED CONTEXT] SOUL.md
    - ## 🛡️ [CORE AUTHORITY] USER.md
    - ## 📄 [EXTENDED CONTEXT] USER.md
    - ## 🛡️ [CORE AUTHORITY] TOOLS.md
    - ## 📄 [EXTENDED CONTEXT] TOOLS.md
3. **03. MEMORY** (记忆层多层级叠加, Delimiter: ---)
    - # Memory
    - ### 🧠 [PRIMARY EXPERIENCE] (vault/BOT.md)
    - ### 📄 [EXTENDED EXPERIENCE] (workspace/BOT.md)
    - ### 🛡️ [CORE FACTS] (vault/MEMORY.md)
    - ### 📄 [EXTENDED FACTS] (workspace/MEMORY.md)
4. **04. ALWAYS SKILLS** (Delimiter: ---)
    - # Active Skills (优先加载 vault/skills/ 中的定义)
5. **05. SKILLS SUMMARY**
    - # Skills (所有可用技能摘要，Vault 技能标注 source)

### MESSAGES LIST
(来自 session manager 的历史消息序列等)

### 符号说明：
- 🛡️ **[CORE AUTHORITY]**: 核心权威。来源于 Vault，作为 Bot 的基础设定，必须遵循。
- 📄 **[EXTENDED CONTEXT]**: 扩展上下文。来源于 Workspace，作为业务场景或特定项目的补充信息，权重次之。
- 🧠 **[PRIMARY MEMORY]**: 主记忆。Bot 自动总结的、位于存储中受保护的经验记忆。
- 📄 **[SECONDARY FACTS]**: 次要事实。来自于 Workspace 的 `MEMORY.md`，用于兼容原有的记忆流。

## 3. 存储扩展能力 (Vault Capabilities)

除了上图展示的文本上下文外，记忆存储还支持以下高级能力：

### 3.1 永不被覆盖的 Agent Skills
在 `cafeext/vault/skills/` 目录下定义的技能：
- 具有最高加载优先级。
- 如果与 `workspace/skills/` 下存在同名技能，存储中的技能将强制覆盖后者。
- Agent 的 `write_file` 工具受限于 `workspace`，因此无法篡改存储中的技能。

### 3.2 存储级 MCP (Model Context Protocol)
在 `cafeext/vault/mcp.json` 中定义的 MCP 服务器：
- 在系统启动时被自动加载并追加到配置中。
- 用于提供一些基础的、不可被禁用的宿主机操作能力（例如浏览器控制或系统探针）。
