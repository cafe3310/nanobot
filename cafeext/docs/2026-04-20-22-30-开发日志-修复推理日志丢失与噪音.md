# 开发日志：修复流式推理日志丢失与日志噪音问题

## 1. 任务背景
用户反馈在 `nanobot` 升级后，审计日志中丢失了完整的推理请求上下文，且流式回复产生了大量碎碎碎碎碎的碎碎日志。

## 2. 问题诊断
- **丢失上下文**：上游 `nanobot` 默认启用了流式渲染，而 Sidecar 原先仅拦截了 `chat` 方法，未拦截 `chat_stream`，导致所有流式请求绕过了日志记录。
- **日志碎裂**：`MessageBus` 拦截逻辑记录了每一个 `_stream_delta` 消息，导致日志文件中充斥着单字回复。
- **对象兼容性**：v0.1.5+ 返回的是 `LLMResponse` 数据类，而原日志逻辑仍在使用 OpenAI SDK 的 `choices` 对象。

## 3. 解决方案与修改
### 3.1 `launcher.py` (注入修复)
- 增加了对 `OpenAICompatProvider.chat_stream` 的拦截。
- 抽离了通用的 `create_patched_chat` 装饰器。

### 3.2 `logger.py` (数据适配)
- 更新 `cafe_success_callback` 以识别 `LLMResponse` 对象。
- 支持提取并独立展示 `reasoning_content` (思维链/思考过程)。
- 改进了工具调用在日志中的展示方式。

### 3.3 `security.py` (噪音消除)
- 在 `MessageBus.publish_outbound` 拦截逻辑中增加了过滤。
- 识别 `_stream_delta` 属性，仅记录非 Delta 消息（即：完整消息或流结束时的汇总消息）。

## 4. 结果验证
- [x] 流式请求现在能正确生成 `🚀 推理请求` 和 `✨ 推理成功` 日志块。
- [x] `📤 发送回复` 日志现在保持完整，不再碎裂。
- [x] 成功捕获并展示了模型的思维链内容。
