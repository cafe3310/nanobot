# 设计：人格化方案实施方案

## 1. 核心分析 (Insights)

基于需求方案，构建的 Bot 应当具备独特的交流风格，避免程式化的回复。

- **问题分析**: 避免强调「根据指令回答」等固定模式，减少与用户的疏远感。
- **设定目标**: 建立角色化的交流方式。Bot 拥有主观的情感表达和特定的行为逻辑。

---

## 2. 人格机制分解

### 2.1 角色认知：角色设定与猫咪特征
- **机制定义**: 结合猫的性格特征（如：粘人、贪吃、特定时间段的活跃表现）。
- **实现手段**: 
    - 修改 `vault/SOUL.md`: 注入第一人称的性格背景。不提及「作为 AI」、「模型」等词汇。
    - 赋予特定行为逻辑：根据状态调整回复长度和语气。

### 2.2 表达习惯：口癖与说话风格
- **机制定义**: 设定固定的结束语或语气词。
- **实施方案**: 
    - 在 `vault/AGENTS.md` 中定义常用词汇表。
    - 进阶：通过技能让 Bot 在不同状态下切换语气词（如：喵、呜、哼）。

### 2.3 情感表达：图片与 Emoji 系统
- **机制定义**: 使用图片和表情进行交流。
- **实施方案**: 
    - 在 `cafeext/media/stickers/` 存放图片资源。
    - 开发 `send_sticker` 工具，允许 Agent 根据语境检索并发送图片。
    - 定义情感与图片的映射关系。

### 2.4 主动性配置 (Proactivity)
- **机制定义**: 具备主动交流的能力，不仅是被动响应。
- **实施方案**: 
    - **心跳机制 (Heartbeat)**: 利用 `nanobot` 的心跳机制，在特定时间发送状态更新。
    - **定时任务 (Cron)**: 设定早晚问候或特定时段的互动逻辑。

### 2.5 记忆深化：人物档案与记录
- **机制定义**: 记录对用户的理解。
- **实施方案**: 
    - **人物档案**: 在 `vault/memory/USER_PROFILES.md` 中记录用户的喜好和近况。
    - **记录视角**: 对话结束后，以 Bot 的视角记录观察内容（存放在 `vault/memory/diaries/`）。

### 2.6 认知关联：联想记忆 (Lore Wiki)
- **机制定义**: 记录事物并建立联想机制。
- **实施方案**: 
    - **记录方式**: 标题简练，内容以第一人称撰写。
    - **联想触发**: 
        - **主动触发**: 利用心跳或定时任务，随机选择条目并结合上下文发送内容。
        - **被动触发**: 指令 Agent 在涉及相关概念时，自然地提及主观倾向。
    - **存储路径**: `vault/wiki/` 目录。

---

## 3. 架构设计 (Vault Layers)

在 `vault/` 目录中建立以下层级：

```text
cafeext/vault/
├── SOUL.md             # 角色设定
├── memory/             # [事实记录层]
│   ├── MEMORY.md       # 长期事实
│   ├── USER_PROFILES/  # 用户及关系档案
│   └── DIARIES/        # Bot 视角的记录
├── wiki/               # [认知关联层] 词典
│   └── {Topic}.md      # 第一人称感悟词条
└── skills/             # [功能配置层]
    ├── vault-sticker/  # 图片发送功能
    └── vault-proactive/# 主动性逻辑
```
