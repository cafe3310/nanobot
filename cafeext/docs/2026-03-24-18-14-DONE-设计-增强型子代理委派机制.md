# 设计：增强型子代理委派机制

## 1. 背景与动机

在复杂的 AI 协作场景中，单一模型往往难以胜任所有任务。例如，主代理使用的推理模型（如 DeepSeek-R1）可能在视觉识别上表现一般，而特定的多模态模型（如 Qwen3.5-35B-A3B 或 Gemini 1.5 Pro）则具备强大的图片理解能力。

为了让 `nanobot` 能够灵活处理多模态任务，我们扩展了原有的 `spawn` 工具，使其支持**模型委派**和**多模态输入**。

---

## 2. 技术实现 (Sidecar Patch)

我们通过 Monkey Patch 的方式对 `nanobot` 核心组件进行了非侵入式增强：

### 2.1 扩展 `SpawnTool` 参数
- **`model` (String)**: 允许显式指定子代理使用的模型 ID。
- **`images` (Array of Strings)**: 支持传入图片的文件路径（相对或绝对）或公开 URL。

### 2.2 增强 `SubagentManager` 逻辑
- **多模态构造**: `_run_subagent` 会自动识别 `images` 列表。
    - 对于**本地路径**：自动读取文件，检测 MIME 类型，并转换为 Base64 数据 URI。
    - 对于**URL**：直接以 `image_url` 形式封装。
- **消息适配**: 自动将 `task` 文本与图片块组合成符合主流 Provider（如 OpenAI, Anthropic, DashScope）规范的多模态消息格式。
- **模型注入**: 在发起推理请求时，动态替换目标模型。

---

## 3. 使用范例

### 3.1 委派图片分析任务
主代理可以像这样调用：
```json
spawn({
  "task": "帮我看看这张截图里，我的系统负载高吗？",
  "images": ["/Users/sipan/Desktop/status.png"],
  "model": "qwen-vl-max",
  "label": "视觉分析"
})
```

### 3.2 委派特定领域的推理
```json
spawn({
  "task": "请用这段复杂的数学公式进行推导...",
  "model": "google/gemini-1.5-pro-002"
})
```

## 4. 安全与审计

- **路径校验**: 所有本地图片路径依然遵循 `nanobot` 的基本安全准则。
- **审计记录**: 在日志中会记录子代理使用的具体模型，方便追踪成本和性能。
