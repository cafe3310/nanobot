# 开发日志：优雅日志系统与全链路审计实现

## 1. 任务背景 (Context)

原有的 JSONL 日志存在「阅读难、转义多、链路断」的问题。为了提升本地调试效率，我们需要一套符合人类直觉、视觉化且覆盖全链路的日志系统。

**核心目标**:
- **视觉化**: 使用 Emoji 区分事件类型。
- **无损单行**: 将 `\n` 替换为 `↵`，彻底消除 `\\\\` 转义地狱。
- **全链路**: 覆盖从消息进入 (`MessageBus`) 到模型推理 (`Provider`) 再到工具执行 (`ToolRegistry`) 的完整闭环。

---

## 2. 取得的成就 (Accomplishments)

### 2.1 优雅日志规范 (Pretty Logging)
- **文件格式**: 切换至 `.log` 后缀，采用结构化纯文本。
- **视觉设计**: 
    - 引入缩进式属性展示 (`attr=val`)。
    - 引入编号式上下文列表 (`01. role: content`)。
    - 使用 `==============================` 分隔不同事件。
- **换行处理**: 实现 `format_content` 算法，将物理换行符无损转化为 `↵` 符号，确保日志单行整齐且可读。

### 2.2 全链路拦截器 (Interceptors)
通过 `cafeext/py/wrapper/security.py` 实施了以下「零侵入」审计点：
1. **[📥/📤] 消息总线 (`MessageBus`)**: 
    - 记录从 Discord/CLI 等渠道收到的原始消息。
    - 记录 Bot 发送回渠道的最终回复。
2. **[🚀/✨] 推理引擎 (`CustomProvider`)**: 
    - 记录发送给 LLM 的 Payload。
    - 自动统计上下文回合数 (`turns`) 和总字符长度 (`total_chars`)。
3. **[🛠️/📦] 工具注册表 (`ToolRegistry`)**: 
    - 记录工具名与传入参数。
    - 记录工具执行时长 (ms) 与返回给模型的原始结果。

## 3. 已实现的 Pretty 记录项 (Logging Schema)

以下是我们针对各类事件提取并美化的核心信息：

| 事件类型 | Emoji | 详细美化内容 (Detailed Info) |
| :--- | :--- | :--- |
| **收到消息** | 📥 | 记录来源渠道 (`channel`)、发送者 (`sender`) 及原始文本。 |
| **推理请求** | 🚀 | 自动计算 `turns` 和 `total_chars`，列出完整的 Context 序列。 |
| **推理成功** | ✨ | 记录 LLM 的生成结果（或工具调用请求）及 API 响应耗时。 |
| **工具执行** | 🛠️ | 记录工具名称及格式化后的 JSON 参数。 |
| **工具响应** | 📦 | 记录执行耗时及结果内容（对超长结果自动截断）。 |
| **发送回复** | 📤 | 记录发送目标渠道及 Bot 的最终输出。 |
