# 调研：模型指令遵循调优观察与进阶方向

## 背景
基于对 `Ling-2.5-1T` 模型的指令遵循（Instruction Following）专项调优，我们成功实现了模型从“社交复读机”到“主动记忆实体”的行为转变。本文记录了调优过程中的核心观察指标，并分析了当前架构下仍存在的潜在提升点。

## 1. 核心观察：行为模式的质变

### 1.1 神经反射的成功建立
- **现象**：在注入「置顶 SOP」后，模型在每一轮会话的第一步，**100% 触发**了对 `memory/SKILL.md` 和 `SOUL.md` 的读取。
- **结论**：证明了**置顶注入 (Top-level Injection)** 能有效对抗长上下文（>10k token）带来的指令稀释效应。模型不再受“中段迷失”影响。

### 1.2 自主探测与闭环意识
- **观察**：在 `tech_acquisition` 测试中，模型听到新术语（cfuse）后，未等用户要求，主动执行了环境探测（`which cfuse`），并在发现缺失后自动生成了安装指南 Wiki。
- **结论**：模型不仅学会了“记录”，还演化出了“主动补全知识盲区”的二级反射。

### 1.3 人格化叙事的深度融合
- **观察**：模型在记录 Wiki 时，能自发地将 `SOUL.md` 的设定（活泼、有主见、方括号心理活动）融入文档。例如，在记录“猫形小饼干”时表达了 Bot 的嗅觉联想。
- **结论**：身份设定不再是死板的约束，而是成为了驱动其记录行为的性格特征。

---

## 2. 观察到的异常与副作用

### 2.1 冗余读取 (Redundant Reads)
- **现象**：在首轮初始化时，模型有时会反复读取同一个文件（如 `MEMORY.md` 读了两次）。
- **分析**：模型为了确保“绝对遵循”，产生了过度补偿行为。这会浪费推理 Token 并增加延迟。

### 2.2 认知惯性 (Cognitive Inertia)
- **现象**：在连续对话中，模型如果第一轮 `list_dir` 过，第二轮往往会跳过搜索直接写入。
- **分析**：模型认为其 Context 已经是最新的（实际也是），但从“每轮必搜”的严格指令来看，这属于指令遵循的软性偏移。

### 2.3 Wiki 目录污染风险
- **现象**：高密度的写入指令导致模型为非常琐碎的事情（如“你好呀”的问候）也创建了 Wiki 词条。
- **风险**：长期运行会导致 `memory/wiki/` 堆积大量低价值文件，降低 `grep` 检索的精度。

## 3. 仍可能提升的点 (Next Steps)

### 3.1 引入「写入权重」评估
- **建议**：在 `memory/SKILL.md` 中增加信息价值评估逻辑。只有当信息包含「新术语」、「新避坑经验」、「显著的用户偏好」时才触发 `write_file`；普通闲聊则记录在 `diaries/`。

### 3.2 优化初始化检测
- **建议**：在 `prompt_patch.py` 中增加状态检测。如果 `nb` 能通过环境变量或注入 context 告诉模型“你已经初始化过了”，模型可以跳过冗余读取，转而直接进入“联想检索”。

### 3.3 自动化 Wiki 整理 (Memory Consolidation)
- **建议**：增加一个名为 `memory-janitor` 的 Cron 任务或心跳逻辑。定期（如每天）让 Bot 回顾 `wiki/` 目录，合并相似条目，清理过期或冗余的信息。

### 3.4 评估脚本的“语义化”升级
- **建议**：目前的 `evaluator.py` 依赖路径包含检查。未来应升级为“LLM 裁判”模式，通过分析工具调用逻辑的合理性来判定 PASS，而不是死板地匹配字符串。
