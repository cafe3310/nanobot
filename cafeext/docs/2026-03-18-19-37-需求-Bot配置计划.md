# 需求：Bot 配置计划

## 1. 背景与目标 (Background & Goals)

本项目基于 `nanobot` 框架，核心目标是集成自研模型并扩展全功能能力。为了确保开发环境的一致性和稳定性，我们需要对项目的初始配置进行系统梳理。本文档旨在提供一份平实的配置参考及其运行注意事项。

## 2. 初始配置步骤 (Initial Setup)

### 步骤 1: 初始化环境 (Onboarding)
运行以下命令以生成默认配置文件 `~/.nanobot/config.json` 及工作区目录：
```bash
nanobot onboard
```

### 步骤 2: 配置模型提供商 (Providers)
在 `~/.nanobot/config.json` 的 `providers` 节点中添加自研 API 端点。
对于 OpenAI 兼容的 API，应使用 `custom` 字段：
```json
{
  "providers": {
    "custom": {
      "apiKey": "your-api-key",
      "apiBase": "http://your-custom-endpoint/v1"
    }
  }
}
```

### 步骤 3: 默认代理设置 (Agents)
在 `agents.defaults` 中指定使用的模型名称，并确保其指向 `custom` provider：
```json
{
  "agents": {
    "defaults": {
      "model": "your-model-name",
      "provider": "custom"
    }
  }
}
```

## 3. 关键配置文件解析 (Config Fields)

| 节点 | 关键项 | 说明 |
| :--- | :--- | :--- |
| `agents.defaults` | `workspace` | 定义 Bot 的存储、会话、日志及文件操作的根目录。 |
| `agents.defaults` | `maxToolIterations` | 限制 Agent 单词请求中允许调用工具的最大次数（默认 40）。 |
| `tools` | `restrictToWorkspace` | **[重要安全项]** 是否将文件操作工具限制在工作区目录内。 |
| `gateway` | `heartbeat` | 控制 `HEARTBEAT.md` 检查的频率和启用状态。 |

## 4. 运行注意事项 (Precautions)

### 4.1 安全性 (Security)
- **敏感信息**: 绝不要在代码中硬编码 `apiKey`。必须将其放置在本地的 `config.json` 中，且避免将该文件纳入版本控制。
- **权限控制**: 默认情况下，文件读写工具对整个用户家目录有访问权限。在生产或调试受控环境时，务必将 `restrictToWorkspace` 设为 `true`。
- **渠道白名单**: 各聊天渠道（如 Telegram, Discord）的 `allowFrom` 字段默认为空。必须显式添加用户 ID，或在测试环境中临时设为 `["*"]`（允许所有人访问，慎用）。

### 4.2 性能与成本 (Efficiency)
- **Token 限制**: 在 `config.json` 中配置合适的 `contextWindowTokens`。AgentLoop 会根据该值自动通过 `MemoryConsolidator` 压缩历史记录。
- **推理成本**: 调用自研模型时，务必注意单次会话的 Token 消耗，防止上下文过大导致的 API 响应超时或失败。

### 4.3 调试技巧 (Debugging)
- **日志开关**: 运行 `nanobot agent --logs` 可实时查看推理过程和工具执行细节。
- **推理原文**: 初始阶段，建议通过扩展 `LLMProvider` 捕获并记录完整的 API 请求/响应 JSON，以便进行模型对齐调试。
