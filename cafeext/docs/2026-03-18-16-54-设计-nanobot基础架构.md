# 设计：nanobot 基础架构

`nanobot` 是一个极简且功能强大的个人 AI 助手框架，旨在以最少的代码量（比 OpenClaw 减少 99%）提供完整的 Agent 能力。它支持多模型、多渠道，并具备强大的工具调用和记忆管理能力。

## 🏗️ 项目架构

项目采用 **Research -> Strategy -> Execution** 的生命周期，核心组件如下：

- **Agent Loop (`nanobot/agent/loop.py`)**: 核心处理引擎，负责接收消息、构建上下文（包含历史、记忆、技能）、调用 LLM、执行工具并返回响应。
- **Message Bus (`nanobot/bus/`)**: 内部消息总线，协调各个 Channel 与 Agent 之间的异步通信。
- **Providers (`nanobot/providers/`)**: 接入 `litellm`，支持 OpenRouter, OpenAI, Anthropic, Gemini, DeepSeek, Ollama 等几乎所有主流模型提供商。
- **Channels (`nanobot/channels/`)**: 多平台接入，支持 Telegram, Discord, Feishu, DingTalk, Slack, WhatsApp, QQ, Email 等。
- **Tool Registry (`nanobot/agent/tools/`)**: 动态工具系统，内置文件操作 (`read`, `write`, `edit`), Shell 执行 (`exec`), 网页搜索/抓取 (`web_search`, `web_fetch`), 以及子代理创建 (`spawn`)。
- **Skills (`nanobot/skills/`)**: 封装好的特定领域能力（如 GitHub, Weather, Tmux），Agent 可通过读取 `SKILL.md` 学习使用。
- **Memory (`nanobot/agent/memory.py`)**: 基于 Token 的记忆压缩与持久化方案。

## 🛠️ 关键命令

### 开发与运行
- `nanobot onboard`: 初始化配置文件 `~/.nanobot/config.json` 和工作空间。
- `nanobot agent`: 启动 CLI 交互模式，可直接与 Agent 对话。
- `nanobot gateway`: 启动网关，连接已配置的所有聊天渠道（如 Telegram, Feishu）。
- `nanobot status`: 查看模型提供商和渠道的连接状态。

### WhatsApp 桥接 (Node.js)
位于 `bridge/` 目录，需独立构建：
```bash
cd bridge
npm install
npm run build
```

## 📝 开发规范

### 环境要求
- **Python**: >= 3.11
- **Node.js**: >= 18 (仅 WhatsApp 桥接需要)

### 技术栈
- **CLI**: [Typer](https://typer.tiangolo.com/)
- **配置/校验**: [Pydantic v2](https://docs.pydantic.dev/)
- **异步**: `asyncio`
- **日志**: `loguru`
- **LLM 接口**: `litellm`
- **Web 抓取**: `httpx`, `readability-lxml`

### 贡献指南
- **添加新 Provider**: 在 `nanobot/providers/registry.py` 中注册并在 `nanobot/config/schema.py` 中添加配置项。
- **添加新 Tool**: 继承 `nanobot.agent.tools.base.Tool`，实现 `execute` 方法和 `to_schema` 定义。
- **添加新 Skill**: 在 `nanobot/skills/` 下创建新目录，包含 `SKILL.md` 描述其用途及使用方法。

## 📂 核心文件索引
- `nanobot/agent/loop.py`: Agent 决策循环逻辑。
- `nanobot/agent/context.py`: 动态提示词与上下文构建。
- `nanobot/config/schema.py`: Pydantic 配置文件结构定义。
- `nanobot/channels/manager.py`: 聊天渠道生命周期管理。
- `pyproject.toml`: 项目依赖与打包配置。
