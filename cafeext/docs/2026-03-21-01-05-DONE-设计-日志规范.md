# 设计：日志格式规范 (Human-Readable Logging)

## 1. 设计初衷

传统的 JSONL 日志虽然利于机器解析，但在本地调试时存在阅读障碍。尤其是复杂转义导致 Payloads 无法直观查阅。

本规范旨在建立一套**结构化、视觉化、无损单行**的日志体系。

---

## 2. 视觉结构 (Visual Structure)

每条日志以 Emoji 开头，通过缩进区分属性与内容，通过分隔符区分事件：

```text
[Emoji 类型] [2026-03-21 01:00:00]
  attr=val
  attr=val
  context:
    - 01. role: 内容 (单行处理，换行替换为 ↵)
    - 02. role: 内容...
==============================
```

---

## 3. 事件类型映射 (Event Types)

- **推理请求 (🚀)**: 发送给 LLM 的完整 Prompt
- **推理响应成功 (✨)**: LLM 生成的最终回复或工具调用请求
- **推理响应报错 (❌)**: API 层面的异常返回
- **工具调用开始 (🛠️)**: 准备执行特定的 Tool
- **工具调用成功 (📦)**: 工具执行完毕并返回结果
- **工具调用报错 (⚠️)**: 工具执行过程中抛出的异常

---

## 4. 核心属性 (Attributes)

针对每次交互，需提取以下关键 `attr`：
- `turns`: 上下文的回合数（Message 列表长度）。
- `total_chars`: 该次推理的总上下文长度（所有消息内容字符总计）。
- `model`: 调用的模型 ID。
- `duration`: 工具执行或 API 调用的耗时。

---

## 5. 内容单行化算法 (Single-Line Formatting)

为了保持日志的整洁并解决转义问题：
1. **替换换行符**: 将所有 `\n` 或 `\r` 替换为特殊符号 `↵` (Return Symbol) 或空格。
2. **压缩空白**: 去除连续多余的空格。
3. **内容保留**: 严禁使用 `json.dumps` 造成的二次转义，直接使用 `ensure_ascii=False` 的原始字符串。

---

## 6. 实现建议

该规范将取代原有的 JSONL 记录器。在 `cafeext/py/callbacks/logger.py` 中实现：
- 废弃 `jsonl` 后缀，改为 `.log` 后缀。
- 在 `context` 列表前，使用循环并附带 `01.`, `02.` 等行号。
