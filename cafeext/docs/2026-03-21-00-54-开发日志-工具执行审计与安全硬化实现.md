# 开发日志：工具执行审计与安全硬化实现

## 1. 任务背景 (Context)

随着 Bot 接入社交平台，其工具调用（Tool Calls）的透明度与安全性变得至关重要。

**需求点**:
- 必须能审计每一个工具调用的「开始」与「结束」状态及结果。
- 必须能物理级禁用危险工具（如 `exec`/`shell`, `spawn`）和技能（如 `clawhub`）。
- 确保所有敏感操作均在 Sidecar 架构的可控沙箱内运行。

## 2. 取得的成就 (Accomplishments)

### 2.1 工具执行全链路审计
- **Monkey Patch 注入**: 对 `nanobot.agent.tools.registry.ToolRegistry.execute` 进行了深度拦截。
- **全链路追踪**: 日志现在包含 `tool_executing` (带参数) 和 `tool_response` (带结果和耗时)。
- **极早期注入机制**: 在 `launcher.py` 中将安全补丁的执行时机提前到任何 `nanobot` 模块导入之前，解决了 Python 模块缓存导致的补丁失效问题。

### 2.2 安全策略硬化 (Security Hardening)
- **危险工具禁用**: 成功禁用了名为 `exec` (即 `shell`) 和 `spawn` 的核心工具。
- **危险技能封锁**: 彻底屏蔽了 `clawhub` 技能。通过对 `SkillsLoader` 的多点拦截（列表、内容、元数据），使 Bot 无法感知或加载该技能。
- **隔离层实现**: 创建了 `cafeext/py/wrapper/security.py` 专门负责安全策略的定义与执行。

## 3. 日志格式与种类 (Log Schema)

推理日志 (`cafeext/logs/yyyy-mm-dd-hh.jsonl`) 现在包含以下标准事件：

### 3.1 推理请求 (request)
记录发送给大模型的完整上下文。
- `type`: `"request"`
- `headers`: 脱敏后的 API Header。
- `payload`: 包含 `messages` 和 `tools` 定义。

### 3.2 工具执行开始 (tool_executing)
在工具实际运行前触发。
- `type`: `"tool_executing"`
- `tool`: 工具名称 (如 `read_file`)。
- `parameters`: LLM 传给工具的原始参数。

### 3.3 工具执行响应 (tool_response)
在工具执行完毕后触发。
- `type`: `"tool_response"`
- `tool`: 工具名称。
- `duration_ms`: 执行耗时（毫秒）。
- `result`: 工具返回的原始字符串（超过 2000 字符会自动截断并标注）。

### 3.4 推理响应 (response)
记录模型最终生成的内容或错误信息。
- `type`: `"response"`
- `status`: `"success"` 或 `"failure"`。
- `payload`: 模型返回的内容或工具调用请求。
