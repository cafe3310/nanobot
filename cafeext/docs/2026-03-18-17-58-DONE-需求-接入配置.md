# 需求：模型对接与 Discord 接入

## 1. 原始诉求 (Original Requirements)

用户希望通过一系列功能实现，将 `nanobot` 发展为一个全功能的智能助手：

1.  **自定义模型对接**：对接用户自定义的模型 API Endpoint (OpenAI 兼容)。
    - *达成标准*: 用户说 "hi"，模型正常回复。
2.  **推理日志透明化**：输出推理日志（发送给 API 的原文及模型回复原文），支持控制台输出并按需写入文本文件，用于调试和分析。
    -   *达成标准*: 推理日志正确输出到控制台和文本文件。
3.  **工作区访问**：Bot 能够拥有并访问一个指定的工作区 (Workspace)。
4.  **Discord 集成**：
    -   发送消息。
    -   接收 @ 提及并回复。
    -   定时阅读群信息并主动回复。
    -   *达成标准*: 在 Discord 中与模型进行闲聊（@ 或非 @ 形式）。
5.  **配置额外功能 (按优先级)**：
    -   文件读写 (带确认执行)。
    -   特定开头的 shell 命令执行 (带确认执行)。
    -   调用 MCP Server (浏览器、系统无障碍)。
    -   调用 Agent Skill。
    -   编写 Agent Skill。

---

## 2. 任务细化与开发指南 (Detailed Roadmap)

### 阶段一：基础连接与调试增强 (优先级：极高)

本阶段目标是确保 Bot 能够稳定连接到自定义模型，并提供详细的调试信息。

-   **任务 1.1：配置自定义 Provider**
    -   在 `config.json` 中配置 `custom` provider。
    -   验证 `apiBase` 和 `apiKey` 的正确传递。
    -   **达成标准**: 通过 `nanobot agent -m "hi"` 获得模型回复。
-   **任务 1.2：实现原始推理日志记录**
    -   修改或扩展 `LLMProvider` 逻辑，在请求前后捕获原始 JSON Payload 和 Response。
    -   在 `nanobot` 运行日志中增加详细的推理块输出。
    -   实现文件日志持久化（例如：`workspace/logs/inference_raw.log`）。
    -   **达成标准**: 在控制台和本地文件中看到完整的 Prompt 和 Completion 原文。
-   **任务 1.3：工作区环境确认**
    -   验证 `onboard` 生成的工作区目录权限。
    -   确保 `AgentLoop` 正确加载该工作区作为默认根目录。

### 阶段二：Discord 渠道集成与主动交互 (优先级：高)

本阶段目标是让 Bot 接入 Discord 平台。

-   **任务 2.1：Discord Bot 基础配置**
    -   申请 Discord Bot Token 并开启 Message Content Intent。
    -   在 `config.json` 中配置 `channels.discord`。
    -   **达成标准**: Bot 在 Discord 服务器上线并能响应 @ 提及。
-   **任务 2.2：实现主动回复与定时阅读**
    -   配置 `Heartbeat` 或 `Cron` 任务。
    -   开发「阅读频道历史」的特定逻辑，评估是否需要主动介入对话。
    -   **达成标准**: Bot 周期性（如每 30 分钟）查看频道并根据上下文主动发言。

### 阶段三：功能扩展 (优先级：中)

本阶段目标是增加 Bot 功能，但必须在人工确认的前提下（Human-in-the-loop）。

-   **任务 3.1：受控的文件读写工具**
    -   为 `WriteFileTool` 和 `EditFileTool` 增加一个「等待用户确认」的拦截机制。
    -   支持通过 CLI 或 Discord 渠道返回确认链接或交互按钮。
-   **任务 3.2：特定前缀的受控 Shell 执行**
    -   配置 `ExecTool` 的命令白名单（前缀校验）。
    -   所有 Shell 操作必须在执行前输出完整命令行并等待用户确认。
-   **任务 3.3：接入 MCP Server**
    -   配置 `mcpServers`（如浏览器控制、无障碍支持）。
    -   验证工具调用链路的连通性。
-   **任务 3.4：Skill 调用与编写**
    -   通过读取 `SKILL.md` 让模型学会调用现有能力。
    -   开发「编写 Skill」的引导逻辑，让模型能自动在 `workspace/skills/` 下生成新的能力定义。
    -   **达成标准**: 模型成功执行一个受控的文件修改操作。
