# 开发日志：推理日志观察与拦截逻辑实现

## 1. 任务背景 (Context)

为了实现对自研模型推理过程的深度审计，我们需要捕获 Bot 发送给 API 的每一条原始 Payload 以及 API 返回的原始 Response。

**挑战**: `nanobot` 的 `custom` provider 直接使用了 `openai-python` 客户端并绕过了 `LiteLLM` 的全局回调机制，导致常规的日志拦截手段失效。

**来源文档**:
- [需求：模型对接与 Discord 接入](../docs/2026-03-18-17-58-需求-模型对接与 Discord 接入.md)
- [定制：Sidecar 附加包启动器](../docs/2026-03-20-20-12-定制功能-Sidecar附加包启动器.md)

## 2. 完成的功能 (Accomplishments)

### 2.1 深度拦截机制 (Monkey Patching)
- 在 `launcher.py` 启动阶段，通过 Python 的 `wraps` 装饰器对 `nanobot.providers.custom_provider.CustomProvider.chat` 方法进行了动态拦截。
- 实现了健壮的参数提取逻辑，能够同时识别位置参数 (`args`) 和关键字参数 (`kwargs`) 中的 `messages` 与 `tools`。

### 2.2 自动化 JSONL 日志系统
- **分时存储**: 自动按小时生成日志文件（如 `cafeext/logs/2026-03-20-21.jsonl`）。
- **标准格式**: 每一行记录为一个独立的 JSON，包含时间戳、操作类型、脱敏 Header 及原始 Payload。
- **安全脱敏**: 对 `Authorization` 等 Header 中的 API Key 进行了「保留首尾、中间遮盖」的处理。

### 2.3 密钥与配置注入
- 实现了从 `cafeext/.env` 到内存配置对象的全自动注入，确保 `config.json` 中无需存储真实的 API Key。

## 3. 技术细节 (Technical Implementation)

- **拦截点**: `CustomProvider.chat`
- **日志路径**: `cafeext/logs/%Y-%m-%d-%H.jsonl`
- **主要模块**:
    - `cafeext/py/wrapper/launcher.py`: 负责 Hook 注入与环境设置。
    - `cafeext/py/callbacks/logger.py`: 负责数据的格式化、脱敏与文件 I/O。

## 4. 遇到的问题与修复 (Troubleshooting)

- **问题现象**: `nb agent` 报错 No API Key
    - **根源分析**: `CustomProvider` 不读取环境变量且 `config.json` 被 Pydantic 强校验。
    - **修复方式**: 通过 Monkey Patch 拦截 `load_config` 函数，在内存中动态注入 Key。
- **问题现象**: `tuple index out of range`
    - **根源分析**: 拦截器死板地访问 `args[0]`，而 `nanobot` 实际使用关键字参数。
    - **修复方式**: 增加对 `kwargs.get('messages')` 的检查，增强兼容性。
- **问题现象**: 401 错误时无日志
    - **根源分析**: 未监听 `failure_callback`。
    - **修复方式**: 补全失败回调函数并注册。
