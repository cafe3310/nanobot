# 定制功能：Sidecar 附加包启动器

## 1. 背景与诉求 (Background & Motivation)

**背景**: 用户希望将 `nanobot` 的配置、记忆数据与核心代码进行统一管理，实现「代码与数据同源」。
**问题**: 
1.  默认情况下 `nanobot` 将数据存储在 `~/.nanobot`，不利于随项目代码一同备份。
2.  直接修改 `nanobot` 源码以更改默认路径会引入上游同步时的冲突。
3.  通过 CLI 参数手动指定路径过于繁琐且容易出错。

## 2. 定制思路 (Design Concept)

我们采用了 **「Sidecar (边车/附加包)」** 架构。将 `nanobot` 核心库视为一个通用的计算引擎，而将用户的所有私有数据（配置、记忆、定制代码）封装在一个名为 `cafeext/` 的独立目录中。

通过一个外部启动器（Launcher），在引擎加载前「劫持」其路径配置，从而实现：
- **零侵入**: 不改动 `nanobot/` 目录下的任何一行源码。
- **全隔离**: 配置和工作区完全锁定在项目目录内的 `cafeext/` 之下。
- **易迁移**: 拷贝整个项目目录即可带走所有记忆和配置。

## 3. 逻辑实现 (Implementation Details)

### 3.1 目录结构
```text
/nanobot-root/
├── .venv/                 # 项目虚拟环境
├── nanobot/               # 上游核心引擎
└── cafeext/               # [核心] Sidecar 附加包
    ├── config.json        # 私有配置文件
    ├── workspace/         # 私有工作区（含 sessions, memory）
    ├── nanobot-shell.sh   # 全局入口脚本
    └── py/
        └── wrapper/
            └── launcher.py # 路径注入逻辑
```

### 3.2 路径穿透与注入逻辑
1.  **Shell 脚本 (`nanobot-shell.sh`)**:
    - 使用 `readlink` 循环穿透物理路径，确保从全局软链接（如 `/usr/local/bin/nb`）启动时，仍能准确定位到项目内的 `.venv`。
    - 负责打印诊断信息（Project Root, Config Dir）。
2.  **Python 包装器 (`launcher.py`)**:
    - 在导入 `nanobot.cli.commands` 之前，调用 `set_config_path()` 将配置文件锁定到 `cafeext/config.json`。
    - 针对 `onboard` 命令，自动注入 `--workspace` 参数，确保初始化操作也在附加包内进行。

## 4. 命令启动方式 (Usage)

### 4.1 全局安装
将包装脚本链接到系统 PATH：
```bash
sudo ln -sf ~/workspace/nanobot/cafeext/nanobot-shell.sh /usr/local/bin/nb
```

### 4.2 常用操作
- **查看状态**: `nb status` (应显示路径指向 cafeext)
- **初始化**: `nb onboard` (自动在 cafeext/ 下生成配置)
- **开始对话**: `nb agent`
- **启动网关**: `nb gateway`

### 4.3 诊断输出
每条命令执行前，控制台会输出如下信息以便审计：
```text
[nb-shell] Project Root: /Users/sipan/workspace/nanobot
[nb-shell] Config Dir:  /Users/sipan/workspace/nanobot/cafeext
[nb-shell] Executing:   nanobot status
```
