# 开发日志：模型切换与内嵌工具调用解析修复

## 背景与问题描述

用户希望将 `opencode` 环境中使用的 `ling-flash-a` (ID: `flash26_mtp_0408`) 模型接入 `nanobot`。在接入并测试过程中，发现该模型在执行推理任务时，倾向于将工具调用（Tool Call）直接以 `<tool_call>` XML 标签的形式嵌入在回复文本中，而非通过标准的 OpenAI API `tool_calls` 字段返回。

由于 `nanobot` 默认的 `CustomProvider` 仅解析 API 返回的结构化工具调用字段，导致 Bot 无法识别并执行嵌入在文本中的工具请求，表现为输出文本后无任何动作。

## 来源文档

- [cafeext/config.json](../config.json)
- [nanobot/providers/custom_provider.py](../../nanobot/providers/custom_provider.py)

## 变更记录

### 1. 模型配置更新
- **环境变量**: 更新 `cafeext/.env` 中的 `CUSTOM_API_KEY` 为 `ling-flash-a` 对应的 Key (`bCHW5...`)。
- **全局配置**: 修改 `cafeext/config.json`，将默认模型切换为 `flash26_mtp_0408`。
- **资源限制**: 根据模型能力，将 `maxTokens` 调整为 `131072`，`contextWindowTokens` 设置为 `262144`。

### 2. 工具调用解析增强 (Sidecar 外挂实现)
- **方案选择**: 采用 Monkey Patch (猴子补丁) 方案，确保 `nanobot` 源码 100% 纯净，降低维护成本。
- **补丁位置**: `cafeext/py/wrapper/model_patch.py`。
- **逻辑实现**: 
    - 在 `launcher.py` 启动阶段拦截 `CustomProvider._parse` 方法。
    - 增加正则表达式提取逻辑，识别文本内容中所有匹配 `<tool_call>(.*?)</tool_call>` 的块。
    - 使用 `json_repair` 对提取到的块进行鲁棒解析，将其转化为 `ToolCallRequest` 对象。
    - 将解析出的工具调用与 API 原生结构化返回的工具调用合并，确保两种来源的请求均能被系统捕获并执行。
- **注入点**: `cafeext/py/wrapper/launcher.py`。

## 验证结论

- **模型连接**: 验证通过，Bot 已成功使用 `flash26_mtp_0408` 进行推理。
- **工具识别**: 测试用例（如“打开煎蛋的页面”）生成的 `<tool_call>` 标签现在能被 `nanobot` 正确提取并触发 `agent_browser` 执行，修复了原有的识别失效问题。
