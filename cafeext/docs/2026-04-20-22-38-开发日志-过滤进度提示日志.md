# 开发日志：过滤工具执行进度提示并确保审计日志语义准确

## 1. 现象
用户反馈在审计日志中，工具执行（如 `ls -la`）会被记录为一条「发送回复」消息，其内容为 `$ ls -la`。这导致日志语义混淆：用户分不清哪些是机器人对用户的真实回复，哪些是机器人正在进行的动作。

## 2. 原因分析
- **进度消息泄露**：`nanobot` 核心在执行工具前会通过 `MessageBus` 发送带有 `_progress=True` 元数据的「进度提示」消息。这原本是为了在 CLI 或 Discord 界面实时展示机器人的“正在执行...”状态。
- **拦截逻辑不足**：原有的审计日志拦截逻辑仅过滤了流式增量包（`_stream_delta`）和结束包（`_stream_end`），未过滤 `_progress` 消息，导致其被误记为「发送回复」。
- **工具审计已存在**：实际上 `security.py` 已经通过 `ToolRegistry.execute` 拦截器正确记录了 `🛠️ 工具执行` 和 `📦 工具响应`。因此，进度提示消息对于审计日志来说是多余的。

## 3. 修复措施
- 修改 `cafeext/py/wrapper/security.py` 中的 `MessageBus.publish_outbound` 拦截逻辑。
- 在元消息（Meta Message）过滤条件中增加对 `_progress` 的识别。
- 确保所有进度消息、流增量消息和流结束信号均不进入审计日志。

## 4. 结果验证
- [x] `$ ls -la` 这类 UI 提示消息不再出现在审计日志的「发送回复」区块中。
- [x] 工具执行过程通过 `🛠️ 工具执行` 和 `📦 工具响应` 两个标准审计块进行记录，语义清晰且包含完整的参数与返回结果。
