# 调研与设计：金库全能化扩展方案 (Vault Omnipotence)

## 1. 核心挑战与解决思路

**挑战**：在早期的安全硬化中，我们全局禁用了 `exec` 工具，以防止 Agent 随意执行 Shell 命令破坏系统。然而，诸如 Git、FFmpeg、ImageMagick 等多媒体与代码管理能力，本质上都依赖底层的 Shell 调用。

**破局思路**：
- **能力请求外部化**: 引入官方标准 MCP 服务器（如 Browser 和 GitHub）。
- **受控 Shell 的复活**: 在 `vault` 中开发一个专用的「白名单命令执行 MCP 服务器」，将 `git`, `ffmpeg`, `gemini`, `magick` 包装成安全的 API。
- **业务逻辑经验化**: 将「如何备份」、「如何整理 Wiki」写成 `vault/skills/` 下的永久记忆指令。

## 2. 八大能力实施方案分解

### 方案 A：引入官方 MCP Server (零代码开发)

针对标准化程度高、生态成熟的需求，直接在 `vault/mcp.json` 中配置官方支持的服务器。

| 目标能力 | 实施方案 | 资源来源 |
| :--- | :--- | :--- |
| **1. 浏览器使用** | 接入官方 Puppeteer MCP | `npx -y @modelcontextprotocol/server-puppeteer` |
| **8. Github Issue 写文章**| 接入官方 GitHub MCP | `npx -y @modelcontextprotocol/server-github` |

*说明：这需要在宿主机安装 Node.js，并在 `vault/mcp.json` 中配置相应的环境变量（如 `GITHUB_PERSONAL_ACCESS_TOKEN`）。*

### 方案 B：开发「白名单沙盒」本地 MCP (解决安全执行)

针对依赖命令行工具的需求，我们将编写一个轻量级的 Python 脚本 `cafeext/vault/mcp/safe_exec_server.py`，它暴露一个名为 `safe_execute` 的工具，但在内部**强校验命令前缀**。

| 目标能力 | 白名单前缀 | 适用场景 |
| :--- | :--- | :--- |
| **2. ImageMagick 处理** | `magick `, `convert ` | 裁剪、压缩、格式转换 |
| **3. Git 处理** | `git ` | 状态检查、提交、推送 |
| **4. FFmpeg 媒体处理** | `ffmpeg `, `ffprobe ` | 视频剪辑、音频提取 |
| **6. 控制 gemini-cli** | `gemini `, `nb ` | 发起子任务、查询其他项目 |

*优势：即使 Agent 产生幻觉尝试执行 `rm -rf`，也会被这个专用的 MCP 服务器在入口处无情拦截。这实现了「既能用 Shell 工具，又绝对安全」的完美平衡。*

### 方案 C：编写 Vault Skills (工作流与认知固化)

对于业务逻辑复杂的复合操作，无需开发新代码，而是利用我们在 `vault/` 中「永不被覆盖的 Skills」特性，教导 Agent 如何使用现有工具（内置读写工具 + 上述 MCP 工具）。

| 目标能力 | Vault Skill 名称 | Skill 核心逻辑 (Prompt 设计要点) |
| :--- | :--- | :--- |
| **5. 整理记忆 Wiki** | `wiki-manager` | 指导 Agent 使用 `list_directory` 扫描 `vault/wiki/`，并使用 `write_file` / `replace` 以固定 Markdown 模板记录事实。定义词条的分类标准和索引更新机制。 |
| **7. 备份 Workspace 与 Vault**| `repo-backup` | 指导 Agent 组合调用 `safe_execute` 执行 `git status`, `git add .`, `git commit -m "Auto-backup"`, `git push`。并且明确规定它在备份前应该忽略哪些临时文件。 |

## 3. 落地实施路线图 (Roadmap)

若您认可此方案，我们将按以下三个阶段实施：

**阶段 1：环境基础设施建设**
1. 创建 `cafeext/vault/mcp/` 目录。
2. 编写 `safe_exec_server.py`（基于官方或轻量级 Python MCP SDK）。
3. 修改 `vault/mcp.json`，配置好 `safe-exec`, `github` 和 `puppeteer` 三个节点。

**阶段 2：编写核心工作流 Skills**
1. 在 `vault/skills/` 下创建 `wiki-manager/SKILL.md`。
2. 在 `vault/skills/` 下创建 `repo-backup/SKILL.md`。

**阶段 3：实战演练与微调**
1. 重启 Bot (`nb agent`)。
2. 尝试下达指令：“帮我给今天的对话写一个 Wiki 词条，然后把项目推送到 Github 备份”。
3. 观察优雅日志中 MCP 调用和文件写入的执行流。
