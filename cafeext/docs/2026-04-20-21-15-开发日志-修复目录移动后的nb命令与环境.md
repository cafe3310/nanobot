# 开发日志：修复目录移动后的 nb 命令与环境

## 背景
用户将项目目录从 `/Users/sipan/workspace/nanobot` 移动到了 `/Users/sipan/workspace/_working/nanobot`，导致全局配置的 `nb` 命令失效。此外，项目的 Python 虚拟环境已被删除，需要重新构建。

## 修复工作
1. **更新全局软链接**：
   - 发现 `/usr/local/bin/nb` 仍然指向旧路径。
   - 使用 `sudo ln -sf` 将其重新链接至新路径下的 `cafeext/nanobot-shell.sh`。
2. **修正配置文件硬编码路径**：
   - 检查发现 `cafeext/config.json` 中的 `agents.defaults.workspace` 字段使用了硬编码的旧路径。
   - 将其更新为：`/Users/sipan/workspace/_working/nanobot/cafeext/workspace`。
3. **重建虚拟环境**：
   - 在项目根目录下通过 `python3 -m venv .venv` 重新创建了虚拟环境。
   - 执行 `pip install -e .` 安装了 `pyproject.toml` 中定义的所有依赖（包括 `typer`, `litellm`, `pydantic`, `loguru` 等）。
4. **验证修复结果**：
   - 运行 `nb --help`，确认命令已恢复正常响应，且能够正确识别项目根目录和附加包配置目录。

## 遗留问题与建议
- **Google 模块警告**：在运行 `nb` 时，`image-gen` 补丁会报 `No module named 'google'`。这不影响基础功能，如果后续需要使用 Google Imagen 生图功能，建议安装 `google-cloud-aiplatform` 相关的依赖。
- **环境稳定性**：如果再次移动目录，建议优先运行 `nb doctor`（Sidecar 自带的诊断工具）进行初步检查，并记得重新创建或修复虚拟环境。
