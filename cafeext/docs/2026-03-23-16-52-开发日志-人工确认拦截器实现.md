# 开发日志：人工确认拦截器实现 (HITL Multi-modal Confirmation)

## 1. 任务背景 (Context)

为了在放开 `exec` 权限后依然保持对 Agent 行为的绝对控制，我们需要在工具执行前注入一个强制的人工决策环节。目标是提供一种既不阻断开发节奏，又能提供高度安全保障的交互方式。

---

## 2. 取得的成就 (Accomplishments)

### 2.1 多维交互确认 (Multi-modal Confirmation)
- **视觉反馈**: 实现了 macOS 原生对话框 (`display dialog`)。通过 AppleScript 强制将确认窗口推至当前活动应用的前台，显示工具名及参数预览。
- **听觉提醒**: 在触发确认面板时同步发出终端响铃 (`\a`)，确保用户即使焦点不在终端也能及时感知。
- **触觉一键化**: 引入了终端 `cbreak` 模式下的单键捕获 (`get_char`)。用户只需按下 `1` (允许) 或 `2` (拒绝) 即可立即做出决定，无需按回车确认。

### 2.2 健壮的拦截架构
- **双重后备**: 如果 macOS 对话框由于权限或环境问题未能通过，系统会自动退回到终端按键确认模式。
- **语义化反馈**: 当用户拒绝执行时，系统会向 Agent 返回标准的 `[Operation Cancelled]` 消息，允许 LLM 理解中断原因并调整后续策略。
- **自动豁免**: 逻辑上自动跳过了 `message` 工具，确保正常的聊天对话不会被频繁打断。

---

## 3. 技术实现细节 (Technical Details)

### 3.1 核心模块
- **`notification.py`**: 封装 AppleScript 逻辑。使用 `frontmost application` 承载对话框，解决了进程无 UI 权限导致弹窗不显示的问题。
- **`security.py`**: 整合拦截逻辑。对 `ToolRegistry.execute` 进行 Monkey Patch，将审计日志、铃声、弹窗、终端捕获串联成完整的执行流水线。

---
