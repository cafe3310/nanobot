# 调研：上下文构建的文件加载清单 (Workspace Injection)

## 1. 任务背景 (Context)

为了设计「记忆存储 (Vault)」和「人格设定覆盖 (Override)」方案，我们需要明确 `nanobot` 核心引擎（特别是 `ContextBuilder`）在构建 System Prompt 时，会从物理磁盘的 `workspace` 目录下抓取哪些文件。

---

## 2. 引导启动文件 (Bootstrap Files)

这些文件位于 `workspace/` 根目录，定义了 Agent 的基础人格和规则。如果存在，它们会被**全量加载**并直接拼接入 System Prompt。

- **加载优先级**: 最高。
- **文件清单**:
    - `AGENTS.md`: 定义 Agent 的核心身份、语气和行为风格。
    - `SOUL.md`: 存放角色的基础价值观、核心约束和预设协议。
    - `USER.md`: 存放关于主人的基本事实和偏好设置。
    - `TOOLS.md`: 存放对工具调用的额外说明或安全禁令。

---

## 3. 记忆系统文件 (Memory Layer)

由 `MemoryStore` 负责管理，是 Agent 跨会话持久化记忆的来源。

- **`MEMORY.md`**: 存放长期事实（Long-term Facts）。这是 Agent 获取经验记忆的物理出口。
- **`HISTORY.md`**: 存放历史交互摘要。虽然不直接全量注入 Prompt，但其物理路径会被告知 Agent，供其通过 `grep` 检索。

---

## 4. 技能描述文件 (Skills Layer)

由 `SkillsLoader` 负责管理，位于 `workspace/skills/` 目录下。

- **`{skill-name}/SKILL.md`**:
    - 对于 `always=true` 的技能：其 `SKILL.md` 内容会**全量注入** System Prompt。
    - 对于普通技能：仅注入 **摘要 (XML Summary)**。Agent 需通过 `read_file` 动态读取完整内容。

---

## 5. 动态运行时上下文 (Runtime Context)

虽然不是预存的物理文件，但在注入 `User Message` 时会动态生成一个元数据块：
- 包含当前时间、渠道 (Channel) 和聊天 ID (Chat ID)。
- 带有一个特殊的运行标志：`[Runtime Context — metadata only, not instructions]`。

---

## 6. 技术拦截建议 (Override Entry Points)

在 Sidecar 架构下，我们可以通过以下「切断点」实现文件的物理覆盖：

1.  **`ContextBuilder.BOOTSTRAP_FILES`**:
    这是一个静态列表。通过 Monkey Patch 修改此列表中的字符串，可以让 Agent 加载我们自定义的文件（如从 `vault/` 映射过来的文件）。
2.  **`MemoryStore.__init__(self, workspace)`**:
    在此处强制将 `self.workspace` 的内部路径重定向到 `cafeext/vault/`。
3.  **`SkillsLoader.__init__(self, workspace)`**:
    同上，实现技能描述文件的物理隔离。

---

## 7. 上下文内存布局 (Context Memory Layout)

以下是发送给 LLM 的完整 Prompt 物理排布示意图（按拼接顺序从上至下）：

### SYSTEM PROMPT
1. **01. IDENTITY**: # nanobot 🐈 (硬编码在 _get_identity)
2. **02. BOOTSTRAP** (Delimiter: ---
    - ## AGENTS.md
    - ## SOUL.md
    - ## USER.md
    - ## TOOLS.md
3. **03. MEMORY** (Delimiter: ---
    - # Memory
    - ## Long-term Memory (来自 MEMORY.md)
4. **04. ALWAYS SKILLS** (Delimiter: ---
    - # Active Skills
    - (全量加载 always=true 的 SKILL.md 内容)
5. **05. SKILLS SUMMARY**
    - # Skills
    - (所有可用技能的 XML 摘要列表)

### MESSAGES LIST
6. **06. HISTORY**: [role: user/assistant/tool] ... (来自 session manager 的历史消息序列)
7. **07. RUNTIME CTX** (User Message 头部): [Runtime Context — metadata only...]
    - Current Time: 2026-03-23 ...
    - Channel: discord / Chat ID: ...
8. **08. CURRENT INPUT** (User Message 内容): [role: user] "主人刚才问我的问题文字或多模态图片内容"

---


### 关键观察：
- **分隔符**: `ContextBuilder` 在 System Prompt 的每一大部分之间使用 `\n\n---\n\n` 进行强隔离。
- **合并策略**: 为了兼容某些 Provider，`Runtime Context` (07) 和 `Current Input` (08) 会被合并为**同一个** `user` 角色的消息，确保不会出现连续的同角色消息。
