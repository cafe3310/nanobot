# 调研：功能扩展体系架构详解 (MCP, Skills, Built-in Tools)

## 1. 任务背景 (Context)

为了在 Sidecar 架构中实施精准的覆盖、禁用或补强逻辑，我们需要明确 `nanobot` 中三种扩展机制（MCP, Skills, Tools）的底层实现、配置文件位置以及它们如何被注入到 LLM 的上下文布局中。

---

## 2. 三大扩展机制全景图

| 机制 | 代码位置 (Logic) | 配置文件/目录 | 核心作用 |
| :--- | :--- | :--- | :--- |
| **内置工具 (Built-in)** | `nanobot/agent/tools/*.py` | `config.json` (可选参数) | 基础能力（文件读写、Shell、Web 搜索等）。 |
| **Agent Skills** | `nanobot/agent/skills.py` | `workspace/skills/` | 通过 Markdown 文档教导 Agent 如何组合使用工具。 |
| **MCP (Model Context Protocol)** | `nanobot/agent/tools/mcp.py` | `config.json` (`mcpServers`) | 接入标准化外部工具集（如浏览器控制）。 |

---

## 3. 详细拆解

### 3.1 内置工具 (Built-in Tools)
- **代码实现**: 定义在 `nanobot/agent/tools/` 下的类（继承自 `Tool`）。
- **加载逻辑**: 由 `AgentLoop._register_default_tools` 统一实例化。
- **配置入口**: `config.json` 中的 `tools` 字段（如 `restrictToWorkspace`）。
- **上下文表现**: 
    - **API 级**: 转换为 OpenAI 函数定义格式，作为 `tools` 参数传递给 LLM API。
    - **Prompt 级**: 不直接出现在 System Prompt 中，除非由 Skill 描述。

### 3.2 Agent Skills
- **代码实现**: `SkillsLoader` 类负责扫描和解析 Markdown。
- **配置文件**: 每个 Skill 必须有一个 `SKILL.md` 文件。
- **加载逻辑**: 扫描 `nanobot/skills/` (内置) 和 `workspace/skills/` (自定义)。
- **上下文表现**: 
    - **Always 模式**: 若元数据标记 `always=true`，其全文注入 System Prompt 的 `# Active Skills` 区块。
    - **Summary 模式**: 其他技能以 XML 摘要形式出现在 `# Skills` 区块，Agent 需动态 `read_file` 读取详情。

### 3.3 MCP 支持
- **代码实现**: `mcp.py` 负责与外部服务器握手并将远程工具映射为本地工具对象。
- **配置入口**: `config.json` 里的 `mcpServers` 字典（定义服务器名、命令、环境）。
- **Sidecar 补强**: 我们额外注入了 `vault/mcp.json` 的合并逻辑。
- **上下文表现**: 
    - **API 级**: 远程工具通过包装器（Wrapper）注册进 `ToolRegistry`，最终作为 `tools` 参数发送。

---

## 4. 上下文内存布局 (扩展视角)

以下展示了这三种能力在发送给 LLM 的 Payload 中的排布：

```text
[ SYSTEM PROMPT (Markdown) ]
+-------------------------------------------------------------+
| ... (Identity & Bootstrap)                                  |
|--------------------|----------------------------------------|
| SKILLS (ALWAYS)    | # Active Skills                        |
|                    | (此处加载标记为 always 的 SKILL.md 内容)  |
|--------------------|----------------------------------------|
| SKILLS (SUMMARY)   | # Skills                               |
|                    | <skills>                               |
|                    |   <skill><name>read_log</name></skill> |
|                    | </skills>                              |
+-------------------------------------------------------------+

[ API TOOLS PARAMETER (JSON) ]
+-------------------------------------------------------------+
| BUILT-IN TOOLS     | [ { "name": "read_file", ... },        |
|                    |   { "name": "exec", ... } ]            |
|--------------------|----------------------------------------|
| MCP TOOLS          | [ { "name": "browser_open", ... },     |
|                    |   { "name": "mcp_custom_tool", ... } ] |
+-------------------------------------------------------------+
```

---

## 5. 配置文件路径归纳

1. **主配置**: `cafeext/config.json` (包含内置工具行为、MCP 服务器列表)。
2. **Sidecar 金库**: 
    - `cafeext/vault/mcp.json` (隐藏的 MCP 配置)。
    - `cafeext/vault/skills/` (受保护的高优先级技能)。
3. **工作区数据**: 
    - `cafeext/workspace/skills/` (用户可修改的技能)。
