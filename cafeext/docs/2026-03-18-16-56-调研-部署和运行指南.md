# 调研报告：nanobot 部署与运行指南

本指南基于对项目源码、CLI 命令及容器化配置的调研编写。

## 1. 部署方式

### 1.1 源码安装 (推荐开发使用)
项目支持使用 `uv` 或 `pip` 进行安装。建议使用 `uv` 以获得更快的依赖处理速度。

```bash
# 克隆仓库
git clone https://github.com/HKUDS/nanobot.git
cd nanobot

# 使用 uv 安装 (可编辑模式)
uv pip install -e .

# 或者使用 pip
pip install -e .
```

### 1.2 Docker 部署
项目提供了 `Dockerfile` 和 `docker-compose.yml`，支持一键容器化部署。

```bash
# 使用 Docker Compose 启动网关
docker compose up -d nanobot-gateway

# 使用 CLI 进行初始化
docker compose run --rm nanobot-cli onboard
```

## 2. 运行流程

### 步骤 1: 初始化 (Onboard)
在首次运行前，需初始化配置文件和工作空间。此操作会在 `~/.nanobot/` 目录下生成默认配置。

```bash
nanobot onboard
```

### 步骤 2: 配置 API 密钥
编辑 `~/.nanobot/config.json`，在 `providers` 部分填入模型提供商（如 OpenRouter, OpenAI 等）的 API 密钥。

### 步骤 3: 运行模式

#### A. 终端交互模式 (CLI Agent)
直接在终端与 Bot 对话，适用于本地测试和任务处理。

```bash
nanobot agent
```

#### B. 全渠道网关模式 (Gateway)
启动网关以连接已配置的所有聊天渠道（Telegram, Discord, Feishu 等）。

```bash
nanobot gateway
```

## 3. 核心管理命令

| 命令 | 说明 |
| :--- | :--- |
| `nanobot status` | 查看当前配置、工作空间及各 Provider 的连接状态。 |
| `nanobot channels list` | 列出所有可用的渠道插件及其启用状态。 |
| `nanobot channels login` | 用于链接需要扫码登录的设备（如 WhatsApp）。 |
| `nanobot provider login` | 执行 OAuth 登录（适用于 OpenAI Codex, GitHub Copilot）。 |

## 4. 注意事项

- **环境要求**: Python >= 3.11。
- **WhatsApp 桥接**: 需安装 Node.js >= 18。源码运行时，`nanobot channels login` 会自动处理桥接器的构建。
- **工作空间**: 默认位于 `~/.nanobot/workspace`，所有 Agent 产生的文件、记忆和定时任务 (Cron) 均存储在此处。
- **端口**: 网关默认运行在 `18790` 端口。
