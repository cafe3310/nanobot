# 设计：项目扩展与防冲突方案

## 1. 背景与核心挑战

在 `nanobot` 基础上开发全功能 Bot 时，核心挑战在于：如何在频繁同步上游 (Upstream) 代码的同时，保留我们自研的模型对齐、推理分析和受控执行等特性。

## 2. 核心策略：外部注入与 Hook 机制

为了尽量少改动 `nanobot/` 目录下的代码，我们采用「外部定义，启动注入」的方案。

### 2.1 目录结构
在项目根目录下建立 `cafeext/` 目录，作为所有自定义功能的存放地：
```text
/nanobot-root/
├── nanobot/           # 上游核心代码 (尽量不改)
├── cafe_docs/         # 项目文档 (doc-todo-log-loop)
└── cafeext/           # [核心] 自研功能扩展
    ├── __init__.py    # 负责在导入时执行 Hook
    ├── providers/     # 自定义模型提供商扩展
    ├── tools/         # 增强版受控工具 (如带确认的文件读写)
    └── callbacks/     # 用于捕获原始推理日志的拦截器
```

### 2.2 启动钩子 (Bootstrapping)
我们仅在 `nanobot/cli/commands.py` 或 `nanobot/__init__.py` 中添加**一行**导入语句：
```python
# 在入口处添加
try:
    import cafeext
except ImportError:
    pass
```
通过在 `cafeext/__init__.py` 中编写注册逻辑，我们可以动态修改 `nanobot` 的全局注册表（如 `PROVIDERS`, `ToolRegistry` 等）。

## 3. 关键功能扩展点 (Extension Points)

### 3.1 原始推理日志 (Raw Inference Logging)
**诉求**: 记录 API 发送和接收的原始 JSON。
**方案**:
- 不要修改 `nanobot/providers/litellm_provider.py`。
- **扩展点**: `litellm` 支持全局回调 (`input_callbacks`, `success_callbacks`)。
- **实现**: 在 `cafeext/callbacks/` 中定义一个记录器，在启动时通过 `litellm.input_callbacks.append(your_func)` 注入。这样可以全局、透明地捕获所有请求原文。

### 3.2 自定义模型 Endpoint 增强
**诉求**: 针对自研模型进行特定参数对齐。
- **扩展点**: `nanobot/providers/registry.py` 中的 `PROVIDERS` 列表。
- **实现**: 在 `cafeext` 初始化时，向该列表 `insert(0, ...)` 我们的自定义 `ProviderSpec`。由于系统会按顺序匹配，我们的扩展将优先生效。

### 3.3 受控执行工具 (Human-in-the-loop)
**诉求**: 文件读写和 Shell 执行需经过人工确认。
- **扩展点**: `nanobot/agent/tools/registry.py`。
- **实现**:
    1.  在 `cafeext/tools/` 下继承 `WriteFileTool`。
    2.  重写 `execute` 方法，在执行前通过 `MessageTool` 或特定的信号量阻塞，并请求用户输入。
    3.  在 `AgentLoop` 启动时，用我们的增强版 Tool 替换掉默认注册的 Tool。

### 3.4 Discord 深度定制
**诉求**: 定时阅读群信息并主动回复。
- **扩展点**: `nanobot/cron/service.py`。
- **实现**: 无需修改 Discord Channel 代码。通过配置一个 `Cron` 任务（每 N 分钟触发），调用 `agent.process_direct`，并在提示词中加入「阅读历史」指令。

---

## 4. 冲突管理规范

1.  **禁区**: 除非万不得已，禁止修改 `nanobot/agent/loop.py` 的核心控制流。
2.  **改动记录**: 如果必须修改核心代码，必须在修改处上方添加 `# CAFE_EXT_FIX` 注释，并在 `cafe_docs` 中记录原因。
3.  **上游同步**: 定期执行 `git fetch upstream`。如有冲突，优先将我们的逻辑提取到 `cafeext` 中，而不是在冲突处强行合入。
